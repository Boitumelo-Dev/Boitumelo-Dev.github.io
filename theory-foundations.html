01 — The core move

Big O: one function bounds another, past a point, up to a constant

Take a messy running-time function and a clean simple one. Big O says: the messy one never rises above a scaled copy of the simple one — not forever from the start, but eventually, once n is large enough. You get to choose the scale c and the starting point n₀.

f(n) = 4n² + 2n + 10 c·g(n) = c·n² region n ≥ n₀
holds f(n) ≤ c·g(n) everywhere in the shaded region.

What to notice: slide c down toward 4 and the smallest valid n₀ races off to infinity; at c = 4 or below, no threshold works. That "4" is exactly the limit of f(n)/g(n) — the boundary between constants that can bound f and constants that can't.

Definition · Big O

f(n) = O(g(n)) if there exist positive constants c and n₀ such that

f(n) ≤ c·g(n)  for all  n ≥ n₀.

Two escape hatches make it forgiving: a constant c (ignore multiplicative factors) and a threshold n₀ (ignore small-n noise). Big O is a ceiling on growth rate.

02 — The master key

Every relation is really a statement about one limit

Chasing constants is fiddly. The notes give a shortcut that unlocks all five symbols at once: divide f by g and see where the ratio settles as n → ∞.

ratio f(n)/g(n) limit c

What to notice: the ratio's destination is the whole story — a finite non-zero number means f and g are the same order (Θ); 0 means f is strictly smaller (o); ∞ means f is strictly bigger (ω). The one-sided symbols O and Ω just allow the boundary values too.

Aha · the limit test

With L = limn→∞ f(n)/g(n):

L = 0  →  f = o(g) and O(g)
L ∈ (0,∞) →  f = Θ(g)  (so O and Ω)
L = ∞  →  f = ω(g) and Ω(g)
03 — The floor

Big Ω: a guaranteed lower bound

Flip the inequality. Ω says a scaled copy of g sits under f eventually — f grows at least this fast. It's the tool for "no algorithm can do better than…".

f(n) = 4n² + 2n + 10 c·g(n) = c·n²

What to notice: raise c above 4 and the lower bound breaks — c·g overtakes f for large n. A valid Ω constant must sit at or below the same limit (4) that capped Big O. Duality: f = O(g) ⟺ g = Ω(f).

Definition · Big Ω
c·g(n) ≤ f(n)  for all  n ≥ n₀.
Limit form: L ∈ ℝ⁺ ∪ {∞}, i.e. the ratio does not collapse to 0.
04 — The tight fit

Big Θ: sandwiched from both sides

Θ is O and Ω at once — f is pinned between two scaled copies of g. This is the honest "the running time is this order", not just an upper or lower guess.

f(n) c₁·g(n) c₂·g(n)

What to notice: the band [c₁·g, c₂·g] has to contain f for all large n. It works precisely when c₁ ≤ 4 ≤ c₂ — the limit lives strictly inside the band. Θ exists iff a single finite non-zero limit exists.

Definition · Big Θ
c₁·g(n) ≤ f(n) ≤ c₂·g(n)  for all  n ≥ n₀.
Equivalently f = O(g) and f = Ω(g). Limit form: L ∈ ℝ⁺ (finite, non-zero).
05 — Strictly smaller

little o: dominated no matter the constant

Big O needs one constant c that works. little o is stricter: every constant works, even absurdly tiny ones. However small you make c, f eventually dips below c·g. That's what "grows strictly slower" means.

f(n) = 3n + 5 c·g(n) = c·n²

What to notice: shrink c toward zero and a valid n₀ always reappears further right — it never becomes impossible. Contrast the Big O hero, where dropping c below 4 killed it outright. little o ⇒ Big O, never the reverse.

Definition · little o
for every c > 0 there is an n₀:  f(n) < c·g(n) ∀ n ≥ n₀.
Limit form: L = 0.
06 — Strictly bigger

little ω: dominates any constant

The mirror of little o. Pick any constant c, however large — f still overtakes c·g eventually. f grows strictly faster than g.

f(n) = 2n³ − 4n² + 2n + 10 c·g(n) = c·n²

What to notice: crank c as high as the slider allows — the amber curve still wins in the end, just later. This is example 4 from the notes: f = ω(n²) because f/n² → ∞.

Definition · little ω
for every c > 0 there is an n₀:  c·g(n) < f(n) ∀ n ≥ n₀.
Limit form: L = ∞.
07 — How they relate

The five symbols, as one family

Tap a relation to see what it claims and how it connects to the others. Think of them like ≤, ≥, =, <, > — but for growth rates.

Aha · the analogy

O is “≤”, Ω is “≥”, Θ is “=”, o is “<”, ω is “>”. And the dualities fall straight out: f = O(g) ⟺ g = Ω(f) and f = o(g) ⟺ g = ω(f) — flip the comparison, flip the sides. The strict ones imply the loose ones: o ⇒ O, ω ⇒ Ω, and Θ = O ∩ Ω.

09 — Property one

Correctness: right answer, every input, and it stops

Before speed matters at all, an algorithm has to actually solve the problem. Correctness is a promise about all valid inputs — and it has two halves.

A(I)↓  — the algorithm terminates on every input
on
R(I, A(I))  — the output is valid for that input
on

What to notice: correctness is an AND across both gates, quantified over ∀ I ∈ 𝓘. Terminating with a wrong answer isn't correct; producing right answers but looping forever on one input isn't correct either.

Definition · correctness
∀ I ∈ 𝓘,  A(I)↓  ∧  R(I, A(I))
𝓘 is the set of valid inputs — narrowed by our assumptions (e.g. "the list is sorted", "values are unique").
10 — Property two

Complexity: best case and worst case are min & max over inputs of one size

Fix the input size n. There are many inputs of that size, each costing a different number of steps. Best case is the cheapest; worst case is the most expensive.

8 different inputs, all of size n. Bar height = steps TA(I).

best case = min worst case = max

What to notice: both are functions of n — reshuffle and the specific min/max inputs change, but the definitions don't. Worst case is what we usually design against, because it's the guarantee that holds no matter which input arrives.

Definition · best & worst case
Tᴬbest(n) = min over I of size n Tᴬ(I)    Tᴬworst(n) = max over I of size n Tᴬ(I)
11 — Property three

Optimality: does the worst case match the problem's floor?

This one compares an algorithm not to its other cases, but to the problem itself. L(n) is the best worst-case any correct algorithm could possibly achieve — the problem's inherent difficulty. An algorithm is optimal when its worst case sits right on that floor.

What to notice: only correct algorithms are in the race (a fast-but-wrong one is disqualified, not optimal). The floor L(n) is a property of the problem; an algorithm is optimal exactly when its worst case is Θ(L(n)) — never below (impossible) and, ideally, not above (wasteful).

Definition · asymptotic optimality
every correct B:  TBworst(n) = Ω(L(n))    A is optimal if  TAworst(n) = O(L(n)) ⇒ Θ(L(n))
L(n) is a lower bound on the worst case of every algorithm — the “best worst case”. Different algorithms may hit their worst case on different inputs; that's fine.
12 — Carry these forward

Three properties, three different questions

The notes are blunt about it: Correctness ≠ Complexity ≠ Optimality. Keep them separate.

Correctness

Is it right?

Valid output and termination, for all valid inputs. A yes/no property of the input–output relation.

Complexity

What does it cost?

Best case = easiest input of size n; worst case = hardest. Described with O / Ω / Θ.

Optimality

Is it as good as possible?

Worst case matches the problem's lower bound L(n). A claim about the algorithm vs the problem.
